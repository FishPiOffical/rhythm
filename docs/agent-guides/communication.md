# 沟通与协查

调研、排错、方案说明及需要用户协助时必读。关联阅读：[开发准入与交付](workflow.md)、[维护与保密](maintenance.md)、[当前环境](environment-framework.md)、[访问控制](security-access.md)。

## 用使用场景解释结论

- 先给结论，再用具体场景说明：什么用户、在什么入口或前置状态下、做了什么、原本应发生什么、实际发生什么、会造成什么影响。语言简单易懂，同时保留触发条件、影响范围、例外和兼容风险；不能只报类名、异常名或一句“有缓存问题”。
- 场景必须对应已有证据；仅根据代码推演时明确标为推演，尚未复现时直接说明，不编造线上用户、事故或验证结果。按结论、场景、证据与限制组织，技术位置和日志用于支撑结论，不让用户自行从代码片段推导业务影响。
- 区分已证实的原因、待验证的推测和仍缺的证据；多个问题分别说明，不把严重程度、发生概率或受影响人群猜成事实。简单问题可用一段话讲完，不为套格式扩写，但不能省略理解问题所必需的信息。
- 表达示例（仅说明写法，不代表当前故障结论）：“用户登录后打开设置页，停留期间后台更新在线状态，再点击保存，本应保存成功，却可能提示校验失败。按代码推演，后台更新可能使页面令牌失效；尚需核对线上版本和失败时段日志，确认实际是否走到这条链路。”随后列明实际核对的代码位置及尚未验证的条件。

## 说明下一步并集中确认

- 排错任务未完成时，回复不能停在现象或部分原因：说明当前进度、下一步具体做什么、该步骤要解决什么疑问，以及是否需要用户提供信息、确认方案或执行测试。已获授权且可独立完成的调查继续执行，不把本可自行查明的问题全部交给用户，也不反复问“要不要继续”。
- 确实依赖用户时，将当前已知且可一起回答的问题按 `1、2、3` 编号集中提出，优先放阻塞结论或实施的事项。每项说清需要确认什么、为何需要、如何提供非敏感结果，以及答复会决定的下一步；有明确候选时列出简短选项，允许按编号快速回答。不为凑三项编造问题，也不把互相依赖、尚无依据的问题一次堆给用户。
- 请求确认时给出具体方案、影响与推荐选择，不能只写“请确认”或以技术术语让用户猜。需要测试时明确入口、操作、预期结果和需反馈的异常，遵守 Java/FTL 重新编译或重启确认及 PC/移动验收要求；业务决定和代码修改仍按开发门禁执行。
- 只在当前任务存在待办、证据缺口或确需用户决策时安排这些动作。任务已经完成、单纯解释已经答清时正常结束，不追加无关任务、增强建议或形式化确认；没有用户待办时可直接说明本轮已完成及验证限制。

## 生产环境 AI 协查

- 本地无法核实实际部署版本、线上日志或数据状态，且这些证据会影响当前判断时，可将“是否方便联系生产环境 AI 协助只读排查”列入待确认问题，说明需要它核对什么。不假定用户一定能联系，也不为可本地解决的问题例行请求生产介入；用户已说明能否联系时沿用答复。
- 用户确认可以联系后，当轮提供一段可直接转发的完整提示词，由用户转发，不擅自联系其他 AI 或外部人员。提示词必须自包含：说明项目、问题场景、时间与时区、已证实事实、待验证推测、明确检查项和返回格式；不能假定对方读过当前对话或具备相同上下文。发出前补齐已知内容，未知信息明确写“未知”，不要把待填模板当成实际调查结论。
- 协查以只读为原则，此次协查不授权生产变更。明确禁止修改代码、配置、数据库、缓存、权限、验证码盾和指纹，禁止重启、部署、拉取或切换版本、清理文件和日志、安装依赖、制造写入请求或主动复现有副作用的业务操作。不能因命令名、SQL 或 HTTP 方法看似读取就假定安全；无法确认副作用时停止该项并说明需要什么授权。
- 提供已核实的文件、日志范围或查询条件；未核实的路径、服务名和表名必须标明，先做只读定位，不猜出一串可直接执行的命令。限制在与问题有关的时间和对象范围，避免全库、全盘扫描及会持锁或带来明显负载的操作；优先已有日志、版本信息和只读账号。不要求对方生成并执行自动修复脚本。
- 提示词及返回材料均执行 [文档保密要求](maintenance.md#文档保密要求)：不读取或转发秘密，不输出完整环境变量、凭据配置、Cookie、令牌、个人隐私或原始敏感日志；只返回必要的非敏感摘要和位置。收到结果后核对环境、版本、时间及证据适用范围，把对方推测继续标为推测；缺证据项集中追问，不能把“生产 AI 说已修复”当作验收。

下列结构用于编写实际转发提示词；发送前逐项替换占位说明，保留全部操作与保密边界：

```text
请协助只读排查 Rhythm 生产环境问题，本次不授权修复或任何生产变更。

问题场景：<用户入口、前置条件、操作、预期与实际结果、影响范围>
发生时间与时区：<已知时间范围；未知则写未知>
本地已证实：<代码依据和验证结果，并说明本地版本>
仍待验证：<推测及缺失证据，不能写成已确认根因>

请依次核对：
1. 通过已有只读信息确认服务环境和实际运行版本，不能只看工作区 HEAD；无法确认则说明。
2. <明确的日志范围、错误类型或代码位置，以及要回答的问题>
3. <确有必要的数据状态检查及筛选条件；无需查库则删除本项>

操作边界：
- 只读观察现有状态，不修改代码、配置、数据库、缓存、权限、验证码盾或指纹。
- 不重启、不部署、不拉取或切换版本、不安装依赖、不清理文件或日志、不执行修复脚本。
- 不发送会写入或触发业务动作的请求，不为复现问题新增数据或改变用户状态。
- 先确认实际路径和查询方式，只检查相关时间及对象，避免全库全盘扫描、持锁或高负载操作。
- 无法确认操作无副作用，或只能通过变更继续时，停止该项并返回原因和所需授权，不自行尝试修复。
- 不读取、输出或转发密码、密钥、令牌、Cookie、验证码、个人隐私及其他涉密内容，也不保留秘密片段。
- 不输出完整环境变量、凭据配置或原始敏感日志；只返回必要的非敏感摘要及文件位置。

请按以下格式返回：
1. 实际核对的环境、运行版本、时间范围和执行的只读检查。
2. 已证实事实及对应证据位置，用使用场景说明影响。
3. 尚未证实的推测、未执行的检查及原因，不能把无结果当作正常。
4. 仍需开发侧或用户确认的问题，按编号列出；需要变更时仅说明方案，不执行。
5. 如实说明是否产生任何变更；若误操作，立即停止并说明影响，不自行补救。
```
