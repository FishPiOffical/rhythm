# 所有 AI 必读：当前问题与规避要求

开始任何任务先阅读本文件和 [专题索引](README.md)，实施前再读 [开发约定](workflow.md) 及命中专题。这里记录影响后续决策的教训和维护方法，详细实现回到相应专题。

## 这次出现的问题

1. **根文件持续膨胀。** 整理前为294行、51,815字符、97,444字节；每个任务追加关键链路后，构建、事务、人工验收和安全检查多次重复，模块细节掩盖了最高优先级约束。以后先搜索已有规则并更新同一处，非最高优先级内容统一放专题，根文件只留约束和入口。
2. **新旧协议同时命令 AI。** 昵称样式一处要求指定1..100个ID，另一处要求全量版本快照。当前处理器和 [快照专题](../api-v3-membership-snapshot-work.md) 已替代旧协议；旧结论不能继续以现行命令形式保留。协议变化须同步替换所有相关约定，历史差异在记录中说明。
3. **临时环境被写成通用事实。** 旧恢复任务的8081、workphone端口归属及临时IPv6目标与当前8080冲突。用户于2026-11-13确认当前开发地址 `http://localhost:8080`；历史记录不覆盖最新明确要求。发送凭据或操作服务前仍须核对实际进程和无凭据响应，不能按旧记录停止其他项目或改数据库。
4. **规则适用范围不清。** “鉴权统一写apiKey”会误改V3 Bearer协议；“至少test-compile”与“不主动Maven”会冲突。必须区分旧接口、V3和独立OpenID/OAuth契约，执行编译遵守用户授权；未运行检查就明确记录，不能伪称通过。
5. **重构后描述未同步。** 验证码核心已集中到 `AnonymousCaptchaShield`，旧条目仍将全部策略归到中间件。说明架构时核对实现与受保护边界；文档更新不构成修改验证码盾或重建指纹的授权。
6. **只测局部带来反复修复。** 既往问题来自未贯通入口、数据形态、权限、模板、生成产物和浏览器真实操作。必须同步检查PC/移动与源码/产物；Java/FTL先明确提醒开发者重新编译或重启并确认，再联调。夹具、截图、构建成功和AI检查不能当完整链路或人工验收通过。
7. **长条目混合不相关职责。** 原文件把捐助与昵称样式、历史与表情、存档与请求解析、转账与举报写在同一条。今后按职责拆分到对应专题，交叉依赖使用链接；迁移须逐项核对，不能删掉同一条中仍有效的另一半。
8. **历史状态混入长期规则。** “本批未改”“当前临时”“尚待实测”等只证明当时状态；迁移SQL不能假定所有数据库都已执行。保留证据、时间和限制，相关任务先查当前状态；不把记录迁走或本地提交当作验收通过。

## 维护规则

- 项目规则的唯一共同入口是根目录 `AGENTS.md`；本目录是其按需读取的组成部分，具有相同约束力。先读索引选择专题，再阅读其关联文档，不能为省上下文跳过命中的安全、兼容、事务和验收要求。
- 根文件只保留最高优先级、跨任务、长期适用的要求。新增架构事实、模块规则、迁移及验收入口须主动维护本目录；优先更新既有专题，新增专题同时更新索引，禁止把细节不断追加回根文件。
- 精简只允许去重、明确适用范围、拆分职责和带依据地替换过期结论；保留完整含义、所有例外与未验证风险。不要靠隐去失败、改业务行为、增限制或复制巨型旧文件假装完成整理。
- 当前用户确认和实际代码须核对；可直接证实的错误同步修正文档，业务规则不明或涉及行为变化则先确认。没有重新验证就不把“已审计”“待验证”升级为当前通过。
- 一次性脚本、抓取副本、迁移核对数据、运行证据放隔离任务目录；需要长期维护的部署/验收记录保留原文件并链接。历史对照不再自动注入每次任务上下文。
- 工作区协作与提交统一遵守 [协作与文档维护](workflow.md#协作与文档维护)：保留无关改动并在可独立工作时继续，提交按任务片段隔离且告知跳过项；自动 commit 每会话只询问一次并记住明确选择，独立 `commit` / `push` 按当前工作区全量授权处理。不得将无关暂存内容误提交，也不得让项目约定覆盖更高优先级的暂停要求。
- 本轮文档整理用户已明确批准，纯规则文档修改不触发代码实施门禁。后续代码任务继续执行 [完整准入与人工验收要求](workflow.md)，不得以本轮确认代替新任务确认。

## Claude 与 Gemini 入口

- Claude Code已有项目入口 `.claude/CLAUDE.md`，通过 `@../AGENTS.md` 导入共同约定；Gemini CLI的根入口 `GEMINI.md` 通过 `@./AGENTS.md` 导入。入口只补充“按根文件读取和维护专题”的要求，不复制业务规则，不循环导入，不另建会冲突的规则集。
- 官方当前说明：Claude Code已支持读取 `AGENTS.md`，实际加载受版本和 `instructionFiles` 设置影响；Gemini CLI默认读取 `GEMINI.md`，可配置其他文件名。这里保留显式入口兼容不同客户端，不能据此保证所有版本/配置已实际加载。
- Claude用 `/memory` 或 `/context all` 检查载入文件；Gemini用 `/memory show` 检查，修改后可 `/memory reload`。这些入口只适用于相关编码工具，不能自动配置普通网页聊天或其他未支持项目上下文的产品。
- 官方依据：[Claude Code项目记忆](https://code.claude.com/docs/en/memory)、[Gemini CLI上下文文件](https://geminicli.com/docs/cli/gemini-md/)。本次只核对文档和入口，未在两个CLI实际启动会话验证。
