普通文章尾部与长篇“更多”共用 ArticleInteraction：读取本人当前赞踩和计数，明确设置up/down或DELETE清除；感谢读取当前费用、状态与次数，确认后POST。打赏区读取当前状态和价格，确认后POST，成功再读取当前状态及受当前阅读权限保护的文章详情 rewardContentHtml，不把回执当正文授权、不自行增加人数或计数。

三个动作按kind+articleId隔离未确认命令和原幂等键，未知结果跨SPA保留、普通token轮换保留，恢复不改意图/费用请求；初次确定4xx允许重新发起，恢复时4xx不能证明先前未提交，继续保留原键。确认成功后必须GET当前状态，失败只重读，历史回执不覆盖后来状态。另一组件提交会废弃在途旧GET。感谢与打赏确认使用当前读取费用，并明确按提交时平台规则结算；服务端现有契约不支持锁定客户端显示的价格。离页/换号取消本人待确认弹窗，迟到读取和正文不能回到旧身份。收费操作后的余额刷新错误独立提示，不将已确认写入报为失败。

移除无其他调用方的 voteArticle/thankArticle/rewardArticle 旧包装及旧本地乐观计数。普通/长篇使用同一响应式组件，未改APP或经典PC/mobile模板。后端仍279注册入口，本批不新增HTTP契约、Java、FTL、SQL或Repository。

尚未迁移评论写入、emoji reaction、感谢评论、采纳、文章编辑发布、文章旧Socket等；新互动计数是读取时状态，不宣称已接实时增量。未完成整个文章模块或完整v3。

## 人工完整用户链路

1. 服务端先由用户通过IDEA重新编译/重启前批Java改动后联调；本批本身只有客户端，不需因本批重启Java。用户站进入他人普通文章，登录后应读取真实赞踩、感谢费用与状态；赞同→取消→反对→取消，各动作确认后GET与计数一致。本人文章/无权限/不可读目标应显示服务端拒绝，不自行增加计数。
2. 感谢：先取消费用确认，网络无POST；确认一次，读取已感谢和当前次数，并核对积分流水。重复进入不能再扣款；余额不足422应允许补足后新请求；匿名文章当前显示0费用时按平台规则确认。
3. 打赏：游客仅见当前价格和登录入口；合法未购买用户确认后读取受保护详情，已购买和作者直接读取，不再POST。取消确认不发送请求。检查正文格式/图片及点击放大，不能通过旧回执HTML或本地缓存解锁。
4. 模拟已提交但响应丢失，离开再回文章或普通/长篇切换，点击“重试本次…”应原方法/参数/幂等键恢复，不另起购买；恢复回执后GET当前状态。模拟写入确认后GET或正文503，只提供重读且不再次POST。费用以提交时平台规则为准，核对流水与当前价格变化。
5. 令牌正常轮换应保留未知命令；退出/换号应清除命令和付费正文。在正文请求或确认弹窗等待时离页/退出，迟到结果不得显示/发送旧账号操作。收费成功后的余额刷新503应明确单独错误，不能提示重复付款。
6. 长篇“更多”重复步骤1/2，长篇打赏槽重复3/4；桌面与390px窄屏检查按钮/确认框/错误和正文无横向溢出，键盘能操作，首屏无新增hydration警告。真实匿名/黑名单/test/验证码和公开API鉴权仍须完整回归。

## 反漏扫与安全复核

无新公网路由、anonymous.viewSkips、上传/下载路径或CDN；保留全局BeforeRequestHandler/匿名验证码/解封链路，不以客户端按钮门替代服务器鉴权。互动及正文私有读取只由当前内存Bearer发起，SSR/游客不发；目标ID、操作与key严格校验，返回仅投影公开状态，不接收客户端费用，未引入数据库或远程抓取。错误/普通标签文本插值，唯一HTML为服务端已清洗的当前详情字段。共享HTTP维持Bearer边界/401轮换/现有风险验证码，认证传输专项通过，生成版本/map扫描通过。真实CSRF/越权/全局防扫描、服务端原子账款/通知、跨实例与真机没有本批验收，不能默认通过。
