# 宠物乱斗第一批

在现有 V3 宠物本人接口下开放 Lv.10 起的陪练、NPC 闯关、材料强化和战报。接口字段见 [API.md](../API.md)。启动新版前在对应的 MySQL 库执行 [迁移](../sql/20261116_api_v3_pet_brawl.sql)，部署脚本须使用当前库的表前缀。

战斗引擎使用定点整数及服务端种子，最多十二回合。首批三关，前三场符合奖励的闯关分别发 5、5、10 材料，胜败都发。强化等级永久按账户与武器保存。开战、发材料、推进关卡、战报和回执同事务，强化带期望等级。陪练使用统一基础数值。重新领养保留账户成长和历史战报，当前宠物仍须满足等级门槛。

使用既有宠物本人写事务、账号锁及验证码流程。新增操作为 brawl-fight 和 brawl-upgrade。本人战报按所有者查询，种子仅内部保存，快照只含物种和出战数据。

本地专项入口为 ApiV3PetBrawlTest。它用隔离数据库走真实服务类、事务、路由和账号权限。人工验收用两个测试账号核对 Lv.9 与 Lv.10，再完成三场闯关，确认材料到账 5、5、10，强化后发起新一场查看实际出战属性，刷新后打开历史战报。PC 与移动端均需验证回放、跳过和战报。真实 MySQL 环境的迁移和人工验收单独记录。


## 第二批实装 PvP

先执行 [PvP 迁移](../sql/20261116_api_v3_pet_brawl_pvp.sql)。报名只针对当前宠物和规则版本。双方各自报名后可异步挑战。开战从账号装备读取当前强化等级，旧报名在换宠后自动失效。当前匹配按等级接近程度排序，最大等级差 5，最多读取 32 名候选。每日主动 3 场、被挑战 6 场，按账号和北京时间统计，每对账号每日唯一。

现有第一方事务先取得全局客户端行锁，再锁当前用户。PvP 沿用该串行入口，对手用户行使用 SKIP LOCKED，锁到后读取并锁定其当前宠物。配对、双方额度来源、战报和幂等回执同事务。老战报依旧按原快照读取，PvP 战报使用配对记录授权和翻转视角。新 PvP 战报将双方宠物和主人的显示名保存在原出战配置快照中，读取回放时无需查询当前资料，也不受随后修改昵称影响。匹配阶段的已读配置不依赖在线状态。

人工核对可使用两个 Lv.10 账号，先给一方强化并保存对应报名武器。另一方离线后发起挑战，打开战报查看强化和对应生命。再用第二个账号刷新战报，核对相同对局和本人视角。尝试退出报名、同日重复配对、第三个账号直接查看战报。

## 第三批积分强化

本地启动前执行 [订单迁移](../sql/20261116_api_v3_pet_brawl_orders.sql)。同一档强化可用免费历练材料，或通过本人报价订单选择部分材料并付剩余积分。每份历练材料抵扣 10 积分。报价以当前宠物、武器等级和规则版本冻结，10 分钟后过期。关闭弹窗后可从最近订单重新打开报价。

确认在业务事务前取得账号和系统的积分转账锁，再复用宠物风控、本人用户锁和原键回执。订单行锁和已完成状态同时保护不同幂等键的重复确认。积分、材料、强化、流水索引和订单完成状态一起提交。积分流水使用独立类型 58 和来源 pet.brawl.upgrade，另存订单号，旧版积分页与 V3 共用描述投影。

验收时先用余额不足的专用账号生成报价，确认应返回业务错误且不扣材料或积分。补足余额后，模拟确认已提交、浏览器回执断流，再以原键恢复。查询订单、武器、材料和积分流水，应只有一次升级和扣款。换人访问返回 404，直接材料强化与积分确认竞争时只允许同等级升级一次。

## 第四批进阶配装

本地启动前执行 [进阶配装迁移](../sql/20261116_api_v3_pet_brawl_gear.sql)。神器要求当前武器 +5，每件武器独立解锁第二槽。第一槽使用魂珠，第二槽使用符石，各两种、最高三级。魂珠和符石属于账号，同一道具同一时间只可在一件武器上，拆卸免费。强化及镶嵌在现有本人账号锁下结算，购买复用积分订单与流水。

乱斗页先选武器，在「积分强化与订单」选择进阶项目并确认报价，再用「进阶配装」保存镶嵌。配装使用独立版本防止旧标签页覆盖当前值，换宠保留已购资产与配装。确认当前武器的变化后再开一场 PvP，可在双方战报中看到出战增益。拆卸后下一场按新配置结算，旧战报继续显示原属性。

叠加上限在战斗引擎中校验。首批神器增加 0.12 HP 与 0.02 基础伤害，两槽根据镶嵌品提供生命或攻击。修订后对同武器、同招式基础配装进行了 288,000 局成对模拟，完整配装得分率为 71.85%–76.80%，平均 73.93%，平局计半分。异配装的更广泛平衡仍需线上数据核对。

## 第五批赛季与排行榜

执行 [赛季迁移](../sql/20261117_api_v3_pet_brawl_seasons.sql) 启用首季，从迁移当天北京时间零点起每 90 天换季。迁移可重复执行，保留原锚点。PvP 对局持有共享赛季锁直到提交，战报、双方评级和回执同事务写入。结算任务每分钟检查一次，等待当前在途对局提交后更新结算水位。结束赛季的战绩随后只读，结算重跑保持相同名次。

实装 PvP 双方从 1,000 分开始，按 Elo（K=24）加减分，平局各计半分。比赛至少 10 场且不同对手至少 5 位才上榜，按评级、胜场、达到评级的时间和账号 ID 排序。每日匹配次数和配对去重沿用现有规则。NPC、陪练和功能启用前的战报不计入。

结算后的奖励按最终排名发 40／30／20／10 历练材料。本人请求沿用宠物风控与原键恢复，赛季、账号唯一，领奖记录与乱斗材料余额同事务更新。旧季可回查与补领。该奖励不扣积分、不需要当前宠物与参赛时相同。排行榜先按已确认战绩排序，只向第一方登录用户返回公开用户名、昵称及战绩统计。

本地 MySQL 验收可用隔离账号和短时赛季边界，以两场真实对局核对新旧季报告；给旧季账号准备第 9 场历史，实战后核对上榜条件和同分排序。等待结算，两个会话并发领取同一赛季的奖励，核对余额、原回执和唯一领奖记录。再以 PC 和移动端打开乱斗页，切换当前与上一季，验证已领取状态与榜单分页。
