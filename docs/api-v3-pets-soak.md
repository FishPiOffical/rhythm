# 宠物本地长时回归：单轮持久化专项

此工具是外层八小时协调器的一个子任务，不自行计时八小时，不启动 Rhythm，不部署、不连接线上，不修改产品逻辑。它使用现有 `ApiV3PetTest.Fixture` 创建并销毁临时 SQLite 数据库，执行真实 Java 服务、幂等事务、账本及历史读取。用户名、身份和资金全部属于夹具，不读取开发库真实账号。

## 调用约定

```sh
node tools/experiments/api-v3-pets-soak-cycle.mjs \
  --seed 20261113 --steps 120 \
  --cache-dir /tmp/rhythm-pets-soak-classes \
  --summary /tmp/pets-cycle-20261113.json \
  --baseline
```

- `--seed`：Java 随机序列种子，可保存后单独复现；必须是安全整数。
- `--steps`：随机交错步数，1～2000，默认 80。每轮还会执行完整目录预热和五种并发场景。
- `--summary`：JSON 结果路径；通过临时文件原子替换。stdout 同样输出一行最终 JSON。
- `--log`：可选完整 Java 日志路径，默认与摘要同名 `.log`；含断言堆栈。日志不含真实令牌、密码或账号资料。
- `--cache-dir`：本机临时编译目录。源码、JDK 或运行依赖元数据变化时更换指纹；没有变化的后续轮次不再编译。没有使用 Maven，也不下载依赖。
- `--baseline`：本轮先运行前六批 41 组专项。建议首轮与末轮带上，其余轮次改变种子，仅运行随机序列，不需要每轮重复全量基线。

退出码 0 表示本轮全部通过，非零表示失败。摘要包括 `status`、`seed`、`steps`、`fingerprint`、`compiled`、`baselineSuitesPassed`、开始/结束时间、日志路径；序列结果包括操作成功/拒绝计数、每步不变量次数、最后步号和最后操作。失败后应保留摘要与完整日志，按相同种子/步数/源码指纹复现，不能把失败轮悄悄替换成后续成功轮。

编译闭包抽到 `api-v3-pets-test-runtime.mjs`；原 `api-v3-pets-test.mjs` 仍支持一次性隔离编译并运行全部专项，追加默认种子的 80 步测试。共用闭包避免长时入口和普通专项引用不同源码。

## 新增种子序列

测试起点是一个已经领养、六技能各 20、钱包 10000 的隔离夹具，明确保留 9900 的测试资金偏移；没有把这种测试前置视为可实现的生产收益。之后的购买、喂养、休息、出发、领取、制作、事件领奖、改名和重新领养全部经真实服务。前六批仍单独覆盖普通新用户从 100 币与零技能开始的成长、门槛及七日收支。

每轮先验证所有六个地点、十二门课程和六份工作至少成功开始、领取一次；完成三条事件链和三份永久收藏。目录条目顺序按种子打乱，再执行随机交错操作：

- 六类照顾，食品/饮品切换、购买、每日补给及跨日/多日离线；活动未结束即领取、活动占槽下照顾或换宠等预期冲突。
- 课程、工作、探索、成果领取、收藏制作、事件重复领奖和改名。
- 随机换宠与旧 `petId` 迟到命令；重放任意历史成功回执，包含换宠之前的回执。
- 每次成功操作立即重放原键；随机注入购买已经提交但回包丢失的故障，原键恢复后仍仅扣一次钱和发一次物品。
- 无效购买数量、重复补给、未解锁技能、已拥有收藏等明确错误；被拒绝的命令不得改变任何宠物业务表。
- 两个独立连接并发换宠/事件领奖的同键、异键竞争，以及换宠与出发竞争；另核对旧活动快照领取。线程竞争时序由调度器决定，种子只能复现命令顺序，不能保证线程调度完全相同。

每个随机步骤验证：

1. 钱包非负，且等于全部已提交宠物币流水之和加显式夹具偏移；库存等于首次补给、每日补给、活动成果和日常日志的物品净变化，不能出现负库存。
2. 当前宠物经验、亲密度等于该宠物实际活动成果及照顾净变化；四项状态位于 0～100，日成长不超过十次。
3. 工作每日已赚在 0～60、已赚与剩余之和为 60；消费或换宠不改变这个定义。
4. 一账号只有一只当前宠物和至多一个活动槽；领取记录数量与成果数量一致；换宠归档数量匹配实际成功次数。
5. 事件步骤不倒退，永久收藏不丢失；日志分页无重复，日志/聚合读取不产生业务写入。

完整基线另覆盖名称字素/控制字符、身份和权限、接口严格解析、未知字段、余额/材料不足、数值溢出、每个事务写点与 commit/回执故障、坏快照、跨日时钟回拨、旧版本兼容等。种子序列补交错覆盖，不宣称已枚举无限输入组合。

## 验证边界

该工具能发现数据库状态不守恒、回执重放写入、活动和日志兼容问题；它不能替代真实 MySQL 锁语义、网络协议、浏览器布局与长连接测试。每轮 Java 进程和数据库都会重新创建，所以八小时反复执行也不能被称为单个长期运行 JVM 的内存泄漏验证。外层协调器需要分别记录本地真实 HTTP、桌面/窄屏浏览器、弱网与服务进程观测结果。

本轮只修改测试与实验工具；没有公开路由、权限、Cookie、上传下载、静态资源或 CDN 改动。开发者仍需手动验收，不自动视为可发布。

## 工具交付前验证（2026-11-13）

- `--baseline --seed 20261113 --steps 120`：六个基线测试类、原 41 组及新增序列全部退出 0，序列执行 122 次不变量检查。
- `--seed 1 --steps 160`、`--seed 42 --steps 160`：均退出 0，各 162 次不变量；摘要 `compiled=false`，确认后续轮次复用编译缓存。
- 交叉审查补强库存正余额键存在性、摘要异常处理后，`--seed 314159 --steps 160` 退出 0；162 次不变量、15 次提交回包丢失恢复、4 次重新领养、5 种并发竞争通过。
- 按正式协调器的 200 步再测 `--seed 917312 --steps 200`：退出 0，`compiled=false`，约 26 秒；202 次不变量、8 次未知消费恢复、3 次换宠、11 次旧宠物命令拒绝及 5 种并发竞争通过。只读复核确认预热遍历全部 6 地点、12 课程、6 工作，并完成 3 条事件链和 3 份收藏；日常与材料不足等随机分支仍依赖基线的精确异常断言，不把随机拒绝计数当成每一种错误都已覆盖。
- Node 语法与 `git diff --check` 通过；验证码盾 24 项、路由访问 11 项、172 个 JS 文件版本审计通过。

以上是工具交付前冒烟，不代表八小时任务已经完成。外层协调器须记录实际开始/结束时间及每轮结果，再单独生成长时报告。
