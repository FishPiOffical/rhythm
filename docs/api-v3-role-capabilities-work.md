# 网站角色能力恢复（2026-11-14）

## 原因与范围

旧聊天室由 `Label.level3Permitted` 显示管理撤回，服务端 `withdrawLegacy` 复用 `DataModelService.hasPermission(role, 3)`。V3 控制器此前进入固定 `allowModeration=false` 的适配器，网站即使是 OP、管理员或纪律委员也只能撤回本人消息；`/me` 又没有提供这些入口能力。

本次仅补第一方网页能力和撤回适配，不改旧站角色规则，不重写 `/admin`，不扩大第三方 OAuth 客户端权限。无需数据库迁移。新注释使用中文，保留原注释；没有启动或重启本地服务。

## 旧站规则与本次映射

| 操作 | 旧站真实规则 | V3 网页处理 |
| --- | --- | --- |
| 撤回本人普通消息 | 作者不可变用户 ID；普通用户日费用 0、32、64…… | 保留，第三方客户端也仍可使用 |
| 撤回他人普通消息 | 管理员、OP、纪律委员（level3），免计次/费用 | 新增 `capabilities.chatRevokeOthers`；第一方 DELETE 事务内重验当前角色 |
| 撤回红包 | 所有角色均受红包不可撤回规则限制 | 保留 409，不提供管理例外 |
| 查看文章/评论历史 | 本人可查；他人须具体 `commonViewArticleHistory` / `commonViewCommentHistory` 授权且正文可见 | 增加入口提示，历史资源接口原有鉴权保持 |
| 后台入口 | 角色实际包含 `menuAdmin` | `capabilities.canAccessAdmin`，仍导航旧 `/admin`，目标继续独立验证 Cookie 和 URL 权限 |
| 编辑他人文章等后台管理 | 角色具体资源权限，如 `articleUpdateArticleBasic` | 本轮不扩网站写接口，仍使用旧后台 |
| 执法 / zf 命令 | level3 | 已有 V3 普通发布兼容，保留 |
| 全员禁言时发言 | level3 可豁免全员禁言；个人禁言判断仍按既有分支执行 | 保留，不把管理角色当通用绕过 |
| 修改话题/发弹幕 | 沿用禁言限制；话题 16 积分，弹幕真实报价，不因 level3 自动免费 | 保留；弹幕节流中 username=admin 的旧例外没有扩大到所有管理员 |

`isAdmin` 仍仅管理员且第一方令牌为真。OP、纪律委员和超级会员不是同一个角色；超级会员不具有 level3 管理撤回权限。历史与后台入口不能靠角色名称硬编码，需要读取当前角色的 `role_permission`。

公开资料新增 `userRoleId` 仅用于身份配色。`defaultRole` 是默认新手组；`1630553360689` 是新人报道提升后的成员组，不要把两者对调。自定义角色显示接口真实名称，不能据此授予操作能力。

## 鉴权与恢复边界

- `DELETE /api/v3/chat/messages/{id}` 保留 `contentWrite`、共享写限制和空请求体约束，客户端身份只取认证中间件写入的 `ApiV3Processor.IDENTITY.clientId`。
- 仅 `website_v3` 可以进入管理分支。真实授权仍以事务内 `users.getForUpdate(actor)` 的当前角色为准，不采用页面能力或旧令牌用户快照。
- 旧 `withdraw(viewer, id, key)` 继续为 owner-only 入口。第三方新命令/新键即使是管理员也不能撤回别人。
- 原幂等 operation/body/key 不变；同账号、目标和键只能恢复 `{id, removed, cost}` 历史元数据。随后客户端或角色变化时不重做删除、扣费和广播；身份与 scope 校验仍在回放前执行，不返回正文或作者隐私。
- 消息、表态清理、职业撤销、费用和回执仍处于原事务/保存点；只有明确提交才广播。
- `/me` 的全部新增能力对第三方令牌为 false，不返回原权限全集。普通角色也只有明确配置相应历史/后台权限时才显示入口；能力提示不代替资源接口鉴权。
