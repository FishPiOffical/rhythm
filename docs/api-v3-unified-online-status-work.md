# 新旧客户端在线状态统一

## 原因与实现

旧 `UserChannel` 会写数据库 `userOnlineFlag`，V3 已认证实时连接只登记在自己的注册表。公开资料直接读取数据库标志，导致只使用 V3 的用户仍显示离线，也可能读取到旧连接留下的在线标志。

新增 `UserOnlineStatus`，按连接对象和用户 ID 维护当前实例的连接登记。旧用户通道和 V3 所有已认证订阅共用这份登记，未认证连接不计入；V3 只有 ready 发送成功才登记。关闭、撤销授权、传输失败沿原有关闭路径注销，票据过期即使尚未执行定时清理也不计在线。任意有效连接仍在，用户就保持在线。

资料读取接入：V3 公开资料与 `/me`、经典站公开用户卡和个人主页、旧本人 API/OpenID、私信联系人及同城用户摘要。公开资料遵守 `userOnlineStatus`：V3 隐藏该字段，旧 JSON 接口保持布尔结构并返回 false；本人接口读取实际状态，经典主页保留原模板的本人/管理员可见规则。

不调整在线时长结算、进出场广播、多标签播报去重和原数据库字段写入，不新增轮询或资料查询。

## 待人工验收

通过 IDEA 重新编译或重启 Rhythm 后，用两个账号在经典站和 V3 分别打开公开资料卡：

1. 被查看账号只开 V3，确认两边都显示在线。
2. 同时打开经典站与 V3 的多个标签页，依次关闭，最后一个有效连接断开前始终在线；断开后重新打开资料卡确认离线。
3. 关闭在线公开设置，另一账号和游客均不能获得实际在线状态；本人读取仍保留真实状态。
4. 退出账号、撤销会话、断线重连后，确认旧连接不会维持在线或覆盖新身份。

尚未进行更新后服务的双浏览器人工验收，不将专项测试作为该验收的替代。

## 边界

本次仍为当前 JVM 实例的连接状态，未引入 Redis 或跨实例汇总。若线上多个独立 Rhythm 实例分别承接连接和资料请求，需要后续增加共享在线登记或保持实例亲和，不能把本实现当成全站跨节点在线统计。升级需要重启服务，让旧连接重新登记。
