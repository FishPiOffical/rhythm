## 完整人工测试链

1. 从登录页进入注册，核对open/invitation/closed三模式、当前用户名长度、角色、邀请人资格和邀请码要求。选项503应明确报错并可重试，不能默认开放；提交前服务端改变模式仍应按新规则拒绝。无效用户名/手机/邀请码先拒绝，保留名称/真实占用仍以后端判断。
2. 本人填写资料，点“验证并申请短信”，读取当前captchaId并由本人完成极验。检查四字段序列化JSON、无query/userId；验证期间不得修改绑定资料，取消或离页后旧初始化/成功回调不得再发短信。组件不可用应可取消/重试，不能绕过验证。
3. 收到短信后输入6位码、两次密码并选角色，完成应显示注册成功并自行登录；用户名/手机/邀请信息沿原快照。错码/过期/用途不符/预留冲突/模式关闭分别明确拒绝；成功码不可重用。密码测试6/128边界、首尾空白/Unicode保留、控制字符/无效代理字符/确认不一致拒绝。
4. 模拟已提交后响应丢失，页面进入结果未确认，无原完成表单或自动重发；先用新账号密码登录核实。422等确定失败只清提交密码并允许重新输入，验证码上下文保留。短信请求响应丢失时只提示不明，收到码可继续，未收到需本人稍后明确重新申请。
5. 从登录页进入找回密码，手机号+极验申请；受理不能推断账号存在或短信送达。直接在当前页填短信码和两次新密码，成功提示重新登录。也可打开/reset-pwd，手工填写当前手机号/6位码，不应请求旧meta或出现假userId，不将信息写进导航URL。
6. 在可丢弃开发账号上验证重置后旧v3令牌、授权码、Cookie/apiKey/OpenID失效及重新登录；重置不明先尝试新密码，不能自动反复消费验证码。请求在途离页/取消/重新填资料，旧响应不能复活表单；新身份边界建立后迟到重置不得退出新会话。
7. 检查源码/请求/页面和浏览器storage：无明文密码传输/持久化、无验证码或手机号新增到URL，无原始证明日志。移动390px和桌面键盘/触屏、长错误文本、加载禁用与所有阶段需要实测。
8. 真实服务测试新IP匿名校验、黑名单/test、首访/周期验证码、validateCaptcha解封、开发风控关闭及429/503。业务短信极验与全局访问校验均保留，前端不能绕过任一验证。上述真实运行链仍待验。

## 安全与反漏扫结论

六个现有入口在ApiV3AccountProcessor全部挂AnonymousViewCheckMidware，全局Before黑名单先行，不改anonymous.viewSkips/验证码解封/匿名访问范围。新增客户端调用不授予身份、不直接签发Cookie或令牌；完成提交只到原手机号/验证码/用途绑定业务核心，CSRF与请求校验仍为现有后端边界，本批未新增写路由或放宽apiKey兼容。

字段/长度/UTF-8预算/枚举检查、明确快照、迟到响应/销毁、未知完成禁止重发均有隔离测试。资料和错误纯文本、无v-html；无新SQL、远程抓取或上传/下载路径，避免新增注入/SSRF面；不批量枚举账号，受理不推断存在，按钮防在途重复但不能替代服务端限流。仅复用已有固定Geetest脚本源，无新CDN或目录，静态版本/map复扫通过。真实未鉴权/越权/CSRF拒绝、全局风控/限流/目录响应、短信用途/事务和设备验收均未执行，不默认通过。
