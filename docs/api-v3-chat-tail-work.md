# V3 聊天室小尾巴

## 接口与存储

- `GET /api/v3/me/settings/chat-tail`：第一方本人 `profile.read`，返回 `{enabled,text}`。
- `PUT /api/v3/me/settings/chat-tail`：第一方本人 `settings.write`，必须提供 `Idempotency-Key`，请求只能包含上述两字段。
- 未设置默认关闭、空文案；关闭保留已保存文案。开启时必须有可见文字。
- 部署前执行 `sql/20261112_api_v3_chat_tail.sql`。默认表前缀为 `symphony_`，非默认部署需调整。独立 `user_chat_tail` 表的 `oId` 直接使用用户 ID，不另建随机设置 ID。
- 写入与账号状态校验、幂等回执同事务；按用户行串行化。同键重试恢复原操作，不替换为重试时的内容。

## 文案与历史消息

文案是单行纯文本，支持 Emoji，不解析 HTML、Markdown 或 @ 通知。首尾空白规范化；换行、控制符、双向控制字符及坏代理拒绝。服务端以 Java 25 `Pattern \\X` 扩展字素边界限制 24 字，额外限制 512 UTF-16 单元。浏览器 `Intl.Segmenter` 用于即时提示，Unicode 版本有差异时以服务端校验为准，绝不截断后保存。

保存及实际发送时均通过现有文本审核服务。小尾巴只接在 V3 普通消息发布流程，不修改原正文或客户端传入的内容，不接旧版发送、私信、红包、天气、音乐、弹幕。普通文本、文字加图片可生成；纯引用、纯图片（包括多图和涂鸦）及纯媒体不生成。纯图片的 alt 文案不视为正文。

发送事务读取当前设置，写入原消息 JSON 的 `tail: {text}`。历史列表、详情、上下文和实时推送共用消息 DTO 投影，不查询发送人的当前设置。设置修改只影响后续消息；幂等重放不再次读取设置。非法历史尾巴只丢弃尾巴，保留原消息。设置读取失败则终止本次发送，不静默漏掉尾巴。

前端用独立文本节点和稳定 `.fp-chat-tail` 展示，精简模式隐藏该节点；复制、引用、复读继续只取原正文。
