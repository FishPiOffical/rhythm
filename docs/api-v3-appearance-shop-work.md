# 积分外观商城接入（2026-11-12）

## 用户入口与行为

外观模块新增「外观商城」入口，使用全局弹窗，不增加路由。商城有座驾、气泡、头像框三个分类和「我的外观」筛选。购买支持 7/30 天，点击价格后确认；不会自动装备或续费。

- 座驾：派派小电驴、摸鱼纸飞机、深海潜艇。
- 气泡：海盐汽水、落日邮笺、星夜航线。
- 头像框：潮汐、派派邮票、星环。
- 免费和 VIP 外观保留原入口；积分外观独立授权，不以 VIP 身份放行。
- 续期从 `max(服务器当前时间, 原到期时间)` 累加。到期后新消息使用默认外观，历史消息仍使用发送时快照。
- 座驾一次装备一个，卸下不删除购买权益。到期装备不播报，续期后恢复原选择。
- 装备座驾后，服务端在公开在线状态允许时推送进场事件；批量读取权益，不逐人请求。座驾替换该次管理员进场文案，退场仍沿用原管理员配置。
- 前端从左侧播放 4.1 秒，不拦截页面点击；最多排队 3 条，15 秒过期丢弃。遵循减少动态效果偏好。左侧设置的聊天输入栏目可关闭座驾动画，文字公告仍保留。
- 新后端 ready 帧声明 `presenceControl:true`，新版前端才发送 `chat.presence` 帧。首页仅接收聊天消息；聊天室页/悬浮聊天室参与进场。旧后端不识别此能力时不发送新帧；旧客户端保留原进场行为。多标签页继续按用户合并，短暂重连不重复入场（现有节点内注册表范围）。

## 数据与失败处理

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/v3/appearance-shop` | 有界商品目录、服务器价格、报价版本、上下架状态 |
| GET | `/api/v3/me/appearance-items` | 本人权益、到期时间、座驾装备、余额、服务器时间 |
| POST | `/api/v3/me/appearance-purchases` | `productId/days/revision`，幂等购买或续期 |
| PUT | `/api/v3/me/appearance-mount` | `productId` 装备，空字符串卸下 |
| PUT | `/api/v3/me/chat-appearance` | 复用原气泡/头像框装备接口 |

购买/装备携带 `Idempotency-Key`。未知结果保留原内容和原键；令牌正常轮换不清命令，换号/退出清理。写成功后的库存读取失败只重读，不能重扣。商品修价必须同步递增 `revision`，旧报价拒绝后重新确认。样式和素材只映射本地白名单，服务端不返回可执行 CSS 或外部素材地址。

## 发布顺序

1. 备份数据库，在 Rhythm 数据库执行 `sql/20261112_appearance_shop.sql`，库前缀非 `symphony_` 时替换前缀。
2. IDEA 编译并手动重启 Rhythm，再确认四个新接口及原聊天外观接口。
3. 构建发布 website_v3 客户端与 SSR 产物，包含 `public/images/mounts/`。

本次只完成用户商城闭环。价格、上下架暂由数据库商品表维护；尚未新增 `/admin` 可视化商品管理。禁用商品只停止新购买，不剥夺已有权益；修改商品样式须新增稳定 ID/版本，不能改写历史样式。回滚不要删除权益、购买流水或幂等回执。

## 已验证与边界

- 前端类型检查及客户端/SSR 构建。
- website_v3 `node tools/appearance-shop-test.mjs`：响应丢失恢复、重复扣款防护、令牌轮换、换号拒迟到、写成功读失败、新样式白名单。
- 隔离 Chromium API/WS 夹具：1440、1024、768、390 宽度（浅色与暗色）的购买确认、装备、动画、自动清理、无横向溢出；未使用真实积分。
- Rhythm SQLite 专项：购买/续期、索引失败回滚、凭据撤销、旧报价、余额不足、未购买/到期装备拒绝、历史快照不变；现有外观及实时注册表回归通过。
- Java 专项使用隔离 SQL/传输夹具；积分适配器在同事务模拟余额/流水，不替代 MySQL 多进程并发及真实服务器联调。真实迁移、服务重启、真实双账号进场和管理员数据库改价仍需部署环境验收。本次未部署。

## 后端测试复跑

使用 Java 25；先在 IDEA 编译工程，不需要 Maven。设置 `API_V3_TEST_CLASSPATH` 为编译输出与工程依赖的完整 classpath，包含 SQLite、TestNG；执行 `node tools/api-v3-appearance-shop-test.mjs`。脚本重新编译本功能源码，临时目录只替换 HTTP 输出端口以断言状态，测试结束清理。

匿名目录经过 `optionalContent` 和 `AnonymousViewCheckMidware`；库存要求 `profile.read`，消费/装备要求 `settings.write` 与原写门禁，并在事务内重新核验第一方凭据。所有 SQL 参数化；客户端不能指定作者、余额、价格或到期时间。外观消费使用独立积分类型 57 与 `appearance.buy` 来源；积分、索引、权益、购买记录、幂等回执一起提交。
